# Адресация Modbus: 0-based vs 1-based

## 📌 Краткое определение

| Система | Суть | Где используется |
| :--- | :--- | :--- |
| **0-based** | Адресация **с нуля**. Первый элемент имеет адрес `0`. | Внутри PDU-пакета (то, что реально передается по проводам). |
| **1-based** | Адресация **с единицы**. Первый элемент имеет адрес `1`. | В документации устройств, на HMI/SCADA, в среде программирования контроллеров Modicon. |

---

## 🔍 Как это выглядит на практике

Возьмем **холдинговый регистр** (Holding Register) — самый популярный тип данных.

| Что это | 1-based (Modicon) | 0-based (PDU) |
| :--- | :--- | :--- |
| Первый регистр | 40001 | 0x0000 |
| Второй регистр | 40002 | 0x0001 |
| Третий регистр | 40003 | 0x0002 |
| ... | ... | ... |
| N-й регистр | 40000 + N | N - 1 |

## ⚠️ Где возникает путаница

### Ситуация 1: Документация устройства

Производитель пишет в руководстве:
> "Температура находится в регистре 40001"

Вы берете этот адрес и подставляете его в SCADA как есть. **Ошибка!** SCADA, скорее всего, ожидает 0-based адрес. Нужно использовать `0`.

### Ситуация 2: Modbus-шлюз

Вы настраиваете шлюз (например, MOXA или Anybus) для опроса датчика. В поле "Start Address" шлюз ждет 0-based адрес. А в документации датчика написано "Register 1". Вы вводите `1` — и получаете код ошибки **02 (Illegal Data Address)**.

**Правильно:** ввести `0`.

### Ситуация 3: Программирование Modicon PLC

В среде EcoStruxure Control Expert (Unity Pro) вы работаете с 1-based адресами. Если вы хотите прочитать регистр по PDU-адресу `0`, в функции READ_VAR вы указываете адрес `1`.

// Пример в ST (Struct Text) для Modicon M340
READ_VAR(ADR, '%MW1', ...)  // Читает регистр с PDU-адресом 0
